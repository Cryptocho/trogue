# swarm —— 设计文档（终稿，待拍板）

## 题材与定位

**类幸存者（Vampire Survivors-like）迷你版 + 流式世界范例**。

- 主线：单玩家，双摇杆移动，自动战斗为主体，**主动冲刺 + 主动瞄准**为生存手段，**拾取经验/道具**为成长性。
- 元目标（被示例而非普通）：示范**流式世界**——地图大于屏幕，相机跟随玩家，新区块按需生成、远处区块可丢弃；让后来者知道 ECS 不只是"几百个同质实体"，还要会**空间索引 + 流式 chunk 管理**。

> 玩家愿意继续玩的标准：再玩一局。这局比上局活得久、杀得多、有升级抽到想要的武器。

## 体验目标

> 玩 3 分钟之内有「这局比上局久」的成就感；玩 5 分钟之内至少死一次，且每次死亡都能归因到「不该站在那里」「没注意血量」「错过血包」「没绕开强敌」中的某个具体决定。

## 核心循环（一句话）

> 大世界里跑位躲敌群 → 经验球落一地 / 道具刷出 → 自动射杀 + 拾取 → 升级变强（升级抽卡选武器）→ 撑得越久分数越高 → 死。

## 玩家每分钟做哪些重要决定（按权重）

1. **走位（占 50%）**：大世界里哪里钻、哪里绕；敌群围过来时往哪里跑。
2. **升级抽卡（占 20%）**：三选一武器——是补强已有武器还是换新武器？这是成长决策。
3. **冲刺（占 15%）**：冷却中/就绪中/主动按的判断；冲刺方向 + 时机。
4. **主动瞄准（占 10%）**：右键按住强制射击方向；默认仍是自动射最近敌。
5. **道具取舍（占 5%）**：HP 包 / 速度包 / 经验倍率……什么时候吃、放弃哪个。

## 张力与释放

- **张力**：敌群密度 + Boss 战 + 升级抽卡的"被迫"决策 + 资源（HP/冲刺 CD）的稀缺。
- **释放**：升级爆光 + 经验球磁场拾取 + Boss 击杀后的短暂无敌人真空 + 抽到心仪武器的视觉反馈。
- **节拍**：每 25 秒一波（更大更密），每 4 波一个 Boss；无终局——只比分数。

## 第一段体验（0:00 – 1:30）

| 时间 | 事件 | 玩家感受 |
|------|------|---------|
| 0:00 | 游戏开始，3 秒**准备阶段**（无敌人，只有 1 个 HP 包在玩家身边），HUD 显示控制提示 | 学会移动、知道"有道具可拾" |
| 0:03 | 第 1 波启动：4 个普通敌人从玩家视野内边缘刷 | 「这个很弱」 |
| 0:20 | 第 1 波结束、第 2 波启动：6 个敌人、刷速 +20% | 「需要走位了」 |
| 0:40 | 第一次升级：三选一抽卡（近战/远程两种基础武器） | 「这是核心决策！」 |
| 1:00 | 第 3 波结束、Boss 提示："Boss in 5..." | 「要来了」 |
| 1:05 | Boss 在玩家视野内刷出 | 「哇这么大」 |
| 1:30 | 大概率死（或打掉 Boss 拿到双倍经验） | 第一次死亡有明确归因 |

## 终局

- **没有胜利**。只有街机模式"看能撑多久"。
- **失败**：玩家 HP 归零，显示 `DEFEATED — survived <秒> — wave <N> — score <分>`，按 R 重开。
- **重开**：保留 4 个元进度——最高存活秒数、最远到达波数、最高击杀数、累计升级次数。本进程内存，**不持久化**。

## 流式世界（ECS 范例核心卖点）

- **地图尺寸**：256×256 tile（约 4 倍屏幕），远超一次性渲染。
- **相机**：跟随玩家（中心对准）；只渲染相机视野内的实体 + tile。
- **chunk 网格**：地图切成 16×16 tile chunk。**只激活**半径 4 chunk 内的（player chunk + 邻居 chunk = 9 个），共 144×144 tile 真实存在。
- **流式生成**：
  - 玩家进入未激活 chunk → 立即按种子生成静态地形（边界 + 障碍物）；不会"突然出现"。
  - 玩家离开激活区 → 标记 chunk 为"可清理"；敌群/子弹/经验球**就地保留数据**（不丢，玩家可能绕回），但**停止模拟**（节省 CPU）。
  - 每 8 秒清理一次已不在激活区且无实体的 chunk。
- **chunk 内部障碍物**：每个 chunk 在生成时用 chunk 坐标 + 种子生成 0~3 个静态障碍（L 形墙/石块），不可破坏。
- **chunk 内部道具**：每个 chunk 在生成时以低概率刷 1 个拾取道具（HP 包 / 速度包 / 经验倍率），拾取后该 chunk 不会再刷；可由程序持续生成。

## 武器与升级抽卡

- **起始武器**：玩家出生带 1 把基础远程武器（autofire）+ 1 把基础近战（绕身挥击）。
- **升级抽卡**：每次升 1 级，弹出 3 选 1 抽卡界面：
  - 已有武器 +1 等级（升 1 = +10% 伤害 +5% 射速）
  - 新武器（从池中抽一个未持有的）
  - 武器池（终稿阶段定，先列 6 把）：基础枪、霰弹枪、激光、火箭弹、近战剑、近战光环
- **抽卡界面**：屏幕中央三张卡牌横排，鼠标点击选择；暂停 sim 推进。Esc 取消（随机选第一个）。
- **每把武器都有独立图标 + 弹药/挥击的独立 Sprite**——这是美术成本点，但**值得做**：玩家看到「我的火箭弹是什么样」是类幸存者玩法的灵魂。

## 拾取道具系统

| 道具 | 效果 | 出现率 |
|------|------|--------|
| HP 包（小） | 立即 +25 HP（不超过 max_hp） | 高 |
| 速度包 | 立即 +25% 玩家速度，持续 8 秒 | 中 |
| 经验球 | 已实现（kOrb） | 高 |
| 经验倍率 | 5 秒内拾取经验 ×2 | 低 |
| 无敌小药水 | 立即触发一次冲刺无敌的同等效果（5 秒） | 低 |

**拾取视觉反馈**：拾取瞬间 1 帧放大+闪光（HUD 层做，不进 sim）。不同道具不同色。

## 主动瞄准

- **鼠标右键按住**：玩家射击方向强制为「玩家→鼠标位置」；松开恢复自动。
- **HUD**：右上角小箭头显示当前瞄准方向。

## 暂停

- **Esc 一次**：暂停菜单（半透明覆盖 + "PAUSED — Esc 继续 / R 重开 / Q 退出"）；
- **sim 冻结**：暂停期间 step 不推进、计时不增、波次不刷怪；但**输入仍响应**（玩家可以读 HUD）。
- **再按 Esc**：继续；**R**：重开；**Q**：退出。

## HUD（信息层级 + 视觉）

- **左上**：HP 条（绿→红渐变）+ 数字 `HP / MAX`。
- **左下**：冲刺冷却条 + 数字 `cd`。
- **右上**：瞄准箭头 + 自动/手动模式小标。
- **右上中部**：经验条 `xp / need` + 当前等级 Lv.N。
- **顶部居中**：当前波次 `Wave N — <s> to next` / `Boss in <s>...`。
- **右下**：分数 `Score: <分>`（击杀 ×10 + 拾取 ×5 + Boss ×100 + 升级 ×25）+ 时间 `Time: <分:秒>`。
- **死亡覆盖**：屏幕中央 `DEFEATED — survived <秒> — wave <N> — score <分>` + 4 元进度最高记录。

## 设计边界（确认）

- **不改**：tro-* schema、engine 公共 API、唯一随机源（`tg::Random`）、基础升级规则公式（5/15/25 射速、10/20/30 伤害）。
- **扩展**：sim 层新增 chunk 索引、波次系统、武器池、抽卡状态、道具池；窗口层新增 HUD、流式相机、抽卡 UI、死亡画面、瞄准指示、暂停菜单。
- **可改但不破坏**：自动射最近敌的逻辑保留为基础武器的默认行为；右键瞄准可"覆盖"它。

## 验收标准

- 玩家从冷启动玩一局：能撑过第 1 波；第 1 次升级能看到三选一抽卡；第 4 波能见到 Boss。
- 主动瞄准：右键按住时子弹方向与"玩家→鼠标位置"一致；松开后下个窗口弹幕恢复自动射最近。
- 流式世界：玩家往任一方向跑，地图持续展开，不卡顿；离屏敌人不消耗 CPU；走回原点仍能看到之前的敌群。
- 升级抽卡：每次升级三选一，选后 HUD 出现新武器图标；新武器独立发射/挥击，不覆盖旧武器。
- 暂停：Esc 暂停；step 冻结、波次冻结、计时冻结；Esc 继续。
- 死亡：HP ≤ 0 → DEFEATED 画面 + 4 元进度最高记录；按 R 重开，元进度保留。
- Headless 自动摘要：`wave=`, `boss_kills=`, `time_alive=`, `score=`, `weapon_count=`, `highest_wave=`, `longest_survive=` 等字段。
- **ctest 必须包含**：
  - chunk 流式激活/回收确定性
  - 波次推进（含 Boss 触发）
  - 升级抽卡状态机（弹出 → 选 → 关）
  - 暂停不推进
  - 死亡 → 重置 → 元进度保留
  - 主动瞄准输入覆盖
  - 武器发射/命中独立于其他武器
- **截图自验**：第 1 波开始、第 1 次升级抽卡、Boss 战、暂停菜单、死亡画面（Agent 自读图下结论）。

## 不做（防止范围蔓延）

- 不做音效、粒子、相机摇晃（不属于 ECS 核心循环；美术预算留给武器图标）。
- 不做存档（4 元进度仅内存）。
- 不做难度选项（单曲线，便于范例）。
- 不做成就 / 排行榜 / 解锁。
- 不做 Boss 阶段 / 多阶段 Boss。
- 不改 engine 公共 API 与 tro-* schema。

## 风险与对策

- **chunk 状态序列化**：玩家离屏时敌群数据保留 → 玩家走回仍能遇到原敌群。这要求 ECS 数据结构按 chunk 索引；不是新架构，是 sim 层多一个 `chunk_id[i]` 列。
- **升级抽卡 UI 成本**：三张卡牌横排，每张显示「武器名 + 图标 + 描述 + 是否 NEW」。美术成本集中在 6 把武器的图标 + 弹药 Sprite（6 + 6 = 12 张 16×16 PNG），可用 PixelLab `create_image_pixen` 生成。
- **CPU 占用**：敌上限 200 不变；流式世界减少屏幕外实体渲染但 sim 仍跑所有活跃 chunk 的敌。
- **暂停期间刷分**：暂停时 step 不调用即可；计时也冻结。
- **流式碰撞**：相机视图外的障碍物仍参与碰撞（玩家可能撞飞出去）——这是设计选择，玩家被"打回去"是有反馈的。
