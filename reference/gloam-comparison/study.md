# 苔径留灯：纯 2D 与 HD-2D 对照

这是一道选型题，不是从 HD-2D 迁移到纯 2D。比较的是同一位旅人站在同一盏灯旁时，能否看清路、界石、林缘和它们的远近关系。原 HD-2D 工作树基线为 `79d7400`。

[打开实景对照](index.html)。页面只显示各次运行的 Bevy 主窗口原图；图上没有美术后期。全景与近景各对齐中心附近的比例，不声称整张逐像素对齐：透视和正交的差异正是要看的东西。

## 从 2D 游戏和引擎资料学到了什么

- [Unity 制作组：《Happy Harvest》的 2D 灯光与阴影](https://discussions.unity.com/t/2d-light-and-shadow-techniques-with-the-universal-render-pipeline/1641848)：角色、道具、地块都有颜色以外的法线或蒙版。正常的换灯要让同一物体内部的刻面换亮，而不只是给整张图片染色。制作组还区分了脚下接触影与拉长的投影；做俯视树影时，并不建议所有东西都投无限长的影子。
- [Godot 官方：2D Lights and Shadows](https://docs.godotengine.org/en/stable/tutorials/2d/2d_lights_and_shadows.html)：暗部环境色、点光、方向光和遮光轮廓是不同的输入；灯的虚拟高度可以参与逐像素法线受光，而不需要把画布变成 3D。在[官方示例图](https://docs.godotengine.org/en/stable/_images/2d_lights_and_shadows_enabled.webp)里，不同位置的灯在同一个脸形上留下不同高光，方块的遮挡影却是由轮廓决定的。直接贴一张加色光晕，不能同时替代这两件事。
- [Bevy 0.16.1：2D Bloom 示例](https://github.com/bevyengine/bevy/blob/v0.16.1/examples/2d/bloom_2d.rs)：`Camera2d` 可用 HDR 和 Bloom，没必要为灯罩辉光引入透视镜头。这里只让超阈值的灯芯和亮反光扩散；木桩和石头不是发光体。

## 我们怎样保持公平

|不变|有意改变|
|---|---|
|同一份旅人、界石、碎石和树木的原图、法线、脚底锚点与地图坐标|纯 2D 以脚底排序，远处不会随距离缩小；HD-2D 用透视、深度缓冲和倾斜焦面|
|同一批无夜光烘焙的 4096² 地面颜色、法线和粗糙度纹理，泥路与湿沟位置相同|纯 2D 铺平面、放草蕨图层、计算水洼里的灯光碎反射；HD-2D 有实际地表、草叶与水层几何|
|冷月从左后方来；暖色灯芯在地图 `(1.5, 1.48, 0.83)`；不照亮整片树林|纯 2D 用同一套画布光场给地面和物件着色；HD-2D 用 Bevy PBR、阴影贴图和三维雾|

2D 的虚拟高度只供着色使用。用 RGB 法线区分硬石刻面、苔藓、树皮与斗篷；反转精灵时也要反转法线横轴。地上投影有长度、有方向，脚下另有接触影；它们不是任意物体之间的立体投影。薄雾是随地图位置、层次和离地高度改变的二维混色，不是体积光线步进；水面响应灯光，不是对整片树林做镜面追踪。这几个取舍可以从图上直接判断，不代表纯 2D 必须如此。

## 运行和素材

从当前 Wayland 桌面执行 `tools/gloam/view.sh --2d`；去掉 `--2d` 是 HD-2D。两版都支持滚轮缩放、`B` 切换 Bloom、`F` 切换雾、`F12` 保存主窗口、`Esc` 退出。纯 2D 的 `←` / `→` 从左 / 右照亮界石，数字 `0` 移走验光灯，`N` 切换精灵法线，`S` 切换地面投影。正常进入夜林时没有白色验光灯。HD-2D 的 `D` 控制光学景深；纯 2D 刻意保留全景清晰的线条。

原始 2D 精灵来自本项目的 [PixelLab 导出清单](../../assets/gloam/sprites/manifest.json)；地面来自同一份 [generate_image 材质和加工参数](../../tools/gloam/terrain/parameters.json)。平面灯具是用[独立的 2D 绘制脚本](../../tools/gloam/paper/lantern.py)画的；只复用了原有的木纹素材。都不是把另一版的游戏截图、GLB 或他人游戏画面贴到画布上。

2D 草蕨、落叶和湿沟边界也能[重新生成](../../tools/gloam/paper/ground_art.py)：`uv run --project tools/gloam/terrain tools/gloam/paper/ground_art.py`。草叶用线性法线和逐像素虚拟高度受光，地面投影则只落在地表层，不会像三维阴影贴图那样横跨每一片草叶。

## 实景里看到了什么

同一截路上，纯 2D 保留远树轮廓和路边细线，不靠失焦把远景糊掉；人物与界石附近清楚，后方由偏蓝的薄雾降对比。HD-2D 的前枝更靠近镜头，边缘失焦，灯下草叶在水里也能形成细碎的遮挡和倒影。比较识路时看全景；比较石面和水边时看近景。不以这一幅静物决定全游戏路线。

**界石换灯。** [左灯原图](2d-key-left.png) / [右灯原图](2d-key-right.png)。两次使用同一块法线图、相同取景、白光颜色、强度、高度和距离。先从无光照的原始法线图选样，再对每个源纹素中心对应的截图像素取样：取石身中段（纵向 UV `0.35…0.65`，不透明），按切线法线横轴 `Nx` 分组。表内为 8 位截图的平均亮度 `0.2126R+0.7152G+0.0722B`，并非物理照度。

|石面朝向|源纹素数|左灯|右灯|
|---|---:|---:|---:|
|朝左，`Nx < -0.28`|778|142.11|74.30|
|朝右，`Nx > 0.28`|772|47.31|127.50|

常规近景只关精灵法线，石身中段的平均绝对 RGB 差为 **14.48/255**；旁边未被草覆盖的路面 `[1210,865) → [1260,900)`（左上为原点，右下不含）最大通道差为 **0**。另外从全景单独关闭投影、雾和 Bloom：脚边地面、后排林道、灯芯周边的取样区分别出现平均绝对 RGB 差 6.72、28.76、3.75；没有用整图加色来冒充这三种效果。

## 同桌面性能记录

Ryzen 5 5500 / Radeon RX 6500 XT，RADV Mesa 26.2.7，Vulkan，Wayfire 原生 Wayland。release `--locked --no-default-features`，物理窗口和渲染均 2560×1440、DPI 1、100 Hz、Mailbox/VSync。原型固定种子 841701；全景纵向画幅：纯 2D 11.70 m / HD-2D 32°，近景 6.84 m / 19°。同一构建顺序启动，两版不同时跑。每次素材就绪后预热至少 2 秒、32 帧，接着稳定采样 5 秒；不含冷启动、截图回读与写盘。采样全程有焦点，Wayland 未报告最小化状态，应用未另设帧率上限。

|固定取景|帧数|时长（秒）|应用 FPS|帧时中位数（ms）|P95（ms）|
|---|---:|---:|---:|---:|---:|
|纯 2D 全景|1669|5.001|333.7|2.90|3.85|
|HD-2D 全景|319|5.003|63.8|15.46|16.61|
|纯 2D 近景|1791|5.001|358.1|2.70|3.67|
|HD-2D 近景|336|5.002|67.2|14.67|15.81|

这里数的是应用帧，不是显示器实际显示了多少张不同图片。100 Hz 屏幕不会显示每秒 333 张；表格衡量的是这一个静态场景的渲染余量，不是完整游戏帧率。纯 2D 实景日志：`Mesh2d=1450，Mesh3d=0`（实体数，不是绘制调用数）。本机逐次日志与单项对照图在 `captures/gloam/canvas-study/`；六张用于选型的原图随本页保留。
